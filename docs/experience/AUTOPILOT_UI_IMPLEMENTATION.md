# Codex 自动挡体验实施细则

本文件是自动挡自身的项目实现细则，不是跨产品通用标准。具体颜色、字体、字号、间距和组件参数应与当前面板实现和宿主能力保持一致，并在真实面板中验证。

## 产品任务

面板首先帮助用户回答：

1. 自动挡现在在处理什么；
2. 它是否在做正确的事；
3. 用户是否需要行动；
4. 已经完成了什么，证据在哪里。

## 默认信息顺序

当前工作和阻塞优先，其次是下一步和证据，最后是路线、历史和高级诊断。内部字段、调试日志、重复状态和无法指导用户行动的实现细节不进入默认主路径。

## 必须覆盖的面板状态

- 默认有任务；
- 无任务/空状态；
- 路由或规划中；
- 执行中；
- 等待人工验收；
- 门禁失败；
- 冲突待处理；
- 已落盘/已合并；
- 自动挡暂停或不可用；
- 长文本、长任务和异常数据。

## 宿主与证据

体验验证至少区分面板真实宿主、最小可用面板宽度和项目实际支持的窄屏场景。截图只能证明具体视口和状态曾经渲染；任务是否可理解、可操作和可恢复，仍需任务测试或人工验收。

## 例外

任何偏离通用体验宪法或本细则的实现，必须在 Experience Contract 中说明原因、影响范围和验证证据，不能以“设计稿如此”作为理由。
