# 验收管家：交付前预验收标准

## 目的

用户不是第一道测试。任何工程项在进入「需要你验收」之前，验收管家必须先完成一轮产品级预验收；如果自检失败、证据不完整或结果为 `unknown`，工程项只能返修或补证据，不能通知用户验收。

这条标准适用于前端、后端、全链路、配置、面板和用户可见的工程项。它不要求每个项目使用同一套测试命令，但要求证据类型完整、来源真实、结果可复核。

## 状态机

```text
待自检 -> 自检中 -> 自检失败/证据不足 -> 返修或补证据
                         |
                         v
                   预验收通过
                         |
                         v
                   通知用户验收
                         |
                         v
                 用户通过 / 用户退回
```

`通知用户验收` 的唯一准入条件是四类预验收全部 `pass`。单条截图、单次构建成功、单个接口返回 200、代码已经合并，都不能单独满足准入。

## 四类必经检查

### 1. 工程与后端链路

必须确认：实现已经落盘，接口和数据链路可用，错误路径可控，权限边界成立，失败可以回滚或安全停下。

至少留下以下证据类型：`machine`、`backend`、`integration`、`rollback`。

常见证据包括：针对性测试、类型/构建检查、真实 API 请求与响应、错误响应、数据库或台账回读、回滚/重开路径、命令、cwd、退出码和 commit。

### 2. 前端视觉与交互

必须在真实浏览器或宿主中确认，而不是只看源码、fixture 或静态 HTML：

- 首屏加载完成，关键内容不是“读取中”、空壳或假数据。
- 主要路径可操作，按钮、输入、跳转、刷新、错误和恢复状态都闭环。
- 桌面和窄屏布局没有遮挡、裁切、溢出、错位或文字压叠。
- 视觉层级清楚，字号、间距、颜色、状态、圆角和密度服务于扫描和决策。
- 页面不把 worker、lease、heartbeat、daemon、内部 ID 等工程噪音塞给普通用户。
- 截图展示真实产品结果，能够定位页面、状态和复核路径。

至少留下以下证据类型：`browser`、`screenshot`、`interaction`、`responsive`。

### 3. 小白用户可理解性

验收管家必须用“产品负责人 + 产品设计师 + 第一次使用者”的视角走一遍：

- 只看首屏和截图，能说出产品现在是什么状态。
- 能说出产品替用户做了什么、下一步是什么、什么时候需要用户介入。
- 关键按钮和状态文案不依赖内部术语才能理解。
- 按照复核步骤操作，不需要从代码、日志或聊天记录倒推预期。
- 用户看到的是结果、影响和证据，而不是一堆内部运行读数。

至少留下以下证据类型：`comprehension`、`user_walkthrough`。这不是要求用户替系统做测试，而是验收管家先完成一轮可理解性走查；仍需用户判断的审美、产品方向或真实手感，才进入人工验收。

### 4. PRD 与用户预期对齐

必须对照当前有效的 PRD、产品契约、上下文档案、用户反馈和验收标准，确认：

- 本工程项的预期、非目标和验收条件已经明确。
- 相关用户反馈和已确认约束已经被实现或明确记录为不适用。
- 研究和开源先验已经完成必要的复用判断，不是未经说明地重复造轮子。
- 人工边界、权限边界、回滚边界和失败风险已经展示。
- 没有把不确定事项写成已确认，也没有把 `unknown` 写成 0、正常或完成。

至少留下以下证据类型：`prd`、`expectations`、`acceptance`、`risk`。

## 通过规则

- 四类全部 `pass`：状态为 `ready`，可以把剩余的人工判断送入用户验收台。
- 任一类 `fail` 或 `blocked`：状态为 `blocked`，先返修，不通知用户验收。
- 任一类缺证据或 `unknown`：状态为 `unknown`，先补证据，不通知用户验收。
- 用户退回：保留原证据，重新打开工程项，回到预验收，不得直接改成通过。
- 截图是人工复核附件，不是机器自检替代品，也不自动把工程项改成 `verified`。

## 成本纪律

预验收要复用已有机器门禁、浏览器产物和缓存，不重复喂完整历史上下文；但不能因为 token 或时间成本而跳过真实入口、用户可理解性、失败路径、回滚证据或 PRD 对齐。成本优化只能减少重复读取和无关材料，不能降低交付质量和体验。

## 内置前端共性规范来源

自动挡只抽取知识图谱项目中可跨产品复用的原则：真实浏览器验证、真实结果截图、入口闭环、错误可见、刷新后状态稳定、桌面/窄屏不重叠、读者面降噪、用户结果优先、`unknown` 诚实显示。知识图谱的业务对象、视觉品牌和领域规则不自动复制到其他项目；具体项目规范仍由该项目自己的 `AGENTS.md`、全局规则和产品契约决定。
