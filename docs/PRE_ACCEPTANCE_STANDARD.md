# 验收管家：交付前预验收标准

## 目的

用户不是第一道测试。任何工程项在进入「需要你验收」之前，验收管家必须先完成一轮产品级预验收；如果自检失败、证据不完整或结果为 `unknown`，工程项只能返修或补证据，不能通知用户验收。

这条标准适用于前端、后端、全链路、配置、面板和用户可见的工程项。它不要求每个项目使用同一套测试命令，但要求证据类型完整、来源真实、结果可复核。

## 状态机

```text
待自检 -> 自检中 -> 自检失败/证据不足 -> 返修或补证据
                         |
                         v
                   预验收通过
                         |
                         v
                   通知用户验收
                         |
                         v
                 用户通过 / 用户退回
```

`通知用户验收` 的唯一准入条件是字典中所有**适用的必检项**逐条 `pass`。五类基础检查和三类专项检查只是面板分组，不是通过的最小粒度。专项只在当前任务确实涉及安全、发布或 AI 输出时由动态范围选中；单条截图、单次构建成功、单个接口返回 200、代码已经合并，都不能单独满足准入。

## 可执行验收字典

机器读取的标准源在 `ops/acceptance_dictionary.py`，每条都有稳定编号；真实门禁结果由 `ops/acceptance_evidence.py` 记录，自动保存命令、cwd、退出码、当前 commit、输出尾部和时间：

- `ENG-*`：工程、接口、数据、安全、冲突和回滚。
- `FE-*`：真实浏览器中的加载、布局、响应式、状态、键盘、错误和交互。
- `UX-*`：第一次使用者是否理解状态、结果、下一步和人工边界。
- `PRD-*`：需求、约束、研究、决策、变更和返修闭环。
- `EVD-*`：证据的版本、来源、时间、可复核性和失败保留。
- `SEC-*`：认证、授权、敏感数据、密钥和越权路径。
- `DEP-*`：发布对象、部署命令、生产健康、回滚和监控。
- `AIO-*`：AI 输出结构、事实性、来源追溯、unknown 与降级路径。

每一项至少包含 `id`、`scope`、`severity`、`required`、`method`、
`evidence_required`、`pass_condition`、`fail_condition` 和 `source`。当前字典共
`15 ENG + 34 FE + 15 UX + 14 PRD + 14 EVD + 7 SEC + 7 DEP + 7 AIO = 113` 条标准。面向前端或全链路的工程项不能只选择后端标准；不适用必须显式写成 `not_applicable`，并提供理由、完整证据和当前版本，缺任一项都会被改判为 `unknown`。

### 一条标准怎样才算通过

验收管家为每个 `item_id` 记录一条结果。要得到 `pass`，必须同时满足：

1. `status=pass`，不能由缺省状态推断；只能由真实命令返回 `exit 0` 或对应现场门禁写入。
2. `evidence` 覆盖该条目的全部 `evidence_required`。
3. 有当前测试对象的 `version` 或 `commit`，不能用旧版本或无版本证据。
4. 证据不是 `fixture-only`，且能回到真实入口、命令、浏览器、截图或现场记录。
5. 失败、阻断、错误路径和用户反馈不能被另一条成功记录覆盖；历史记录保留，最新结果负责当前门禁。
6. `not_applicable` 不等于通过；必须写明为什么不适用，并附完整证据和当前版本，否则按 `unknown` 处理。
7. 当动态范围给出 `expected_version` 时，每条证据的版本必须与它一致；旧版本证据只能留在历史里，不能证明当前交付。

以下情况一律不是通过：缺一类证据、`unknown`、`fail`、`blocked`、fixture-only、版本不一致、真实入口不可达、截图与当前版本不一致、`not_applicable` 无理由。

### 面板必须展示什么

“交付前自检”显示总数及 `通过 / 失败 / unknown / 不适用`，并逐条显示标准编号、人话标题、当前状态、通过条件、缺失证据或返修原因。`ready` 之前，“需要你验收”只能为空，并显示“用户暂不需要介入”；不能让用户从日志或源码里找失败原因。

## 基础五类必经检查

### 1. 工程与后端链路

必须确认：实现已经落盘，接口和数据链路可用，错误路径可控，权限边界成立，失败可以回滚或安全停下。

至少留下字典要求的证据：命令与结果、当前版本、真实后端/集成回读、错误路径和回滚或安全停止记录。旧的四类证据标签只用于迁移期摘要，不能单独使逐项标准通过。

常见证据包括：针对性测试、类型/构建检查、真实 API 请求与响应、错误响应、数据库或台账回读、回滚/重开路径、命令、cwd、退出码和 commit。

### 2. 前端视觉与交互

必须在真实浏览器或宿主中确认，而不是只看源码、fixture 或静态 HTML：

- 首屏加载完成，关键内容不是“读取中”、空壳或假数据。
- 主要路径可操作，按钮、输入、跳转、刷新、错误和恢复状态都闭环。
- 桌面和窄屏布局没有遮挡、裁切、溢出、错位或文字压叠。
- 视觉层级清楚，字号、间距、颜色、状态、圆角和密度服务于扫描和决策。
- 页面不把 worker、lease、heartbeat、daemon、内部 ID 等工程噪音塞给普通用户。
- 截图展示真实产品结果，能够定位页面、状态和复核路径。

至少留下字典要求的证据：真实浏览器断言、当前版本截图、交互和响应式结果、console/pageerror 记录以及关键 API 结果。

### 3. 小白用户可理解性

验收管家必须用“产品负责人 + 产品设计师 + 第一次使用者”的视角走一遍：

- 只看首屏和截图，能说出产品现在是什么状态。
- 能说出产品替用户做了什么、下一步是什么、什么时候需要用户介入。
- 关键按钮和状态文案不依赖内部术语才能理解。
- 按照复核步骤操作，不需要从代码、日志或聊天记录倒推预期。
- 用户看到的是结果、影响和证据，而不是一堆内部运行读数。

至少留下字典要求的证据：用户走查步骤、截图和面向用户的清晰文案。这不是要求用户替系统做测试，而是验收管家先完成一轮可理解性走查；仍需用户判断的审美、产品方向或真实手感，才进入人工验收。

### 4. PRD 与用户预期对齐

必须对照当前有效的 PRD、产品契约、上下文档案、用户反馈和验收标准，确认：

- 本工程项的预期、非目标和验收条件已经明确。
- 相关用户反馈和已确认约束已经被实现或明确记录为不适用。
- 研究和开源先验已经完成必要的复用判断，不是未经说明地重复造轮子。
- 人工边界、权限边界、回滚边界和失败风险已经展示。
- 没有把不确定事项写成已确认，也没有把 `unknown` 写成 0、正常或完成。

至少留下字典要求的证据：当前 PRD、决策记录、来源追溯、研究结果和风险处理记录。

### 5. 证据审计

验收管家还要单独检查证据本身，而不是只检查产品结果：每条必检项都有 `item_id`，证据能关联当前工程项，包含时间、版本、命令、cwd、退出码或真实现场记录；失败证据不能被覆盖，旧版本证据不能证明新版本，fixture-only 不能通过，用户验收必须建立在预验收通过之后。

## 三类专项检查

### 6. 安全与权限专项

动态范围识别到权限、登录、账号、租户、敏感数据、token 或密钥影响时启用。必须留下真实认证/授权入口结果、越权拒绝记录、敏感信息与密钥不外泄检查，以及当前版本的安全扫描或等价命令结果。基础工程链路的“权限边界正确”不能替代专项证据。

### 7. 发布与恢复专项

动态范围识别到上线、发布、部署、生产、灰度或回滚影响时启用。必须确认发布对象与验收版本一致、部署命令和退出码可复核、生产健康真实通过、回滚路径已验证或带证据标为不适用、发布后关键入口可达、监控覆盖本次风险。发布动作仍属于用户拍板，不等于机器可以自行上线。

### 8. AI 输出质量专项

动态范围识别到模型、prompt、引用、来源或生成输出影响时启用。必须确认输出结构、事实性来源、引用可回溯、未知明确写成 `unknown`、降级路径不伪装成功、代表性输入有对比结果，且输出不含未授权敏感信息。

没有专项执行器的风险，例如当前性能基线和负载门禁，仍进入 `unmapped_risks` 并阻塞；不能靠基础项绿灯把它抹平。

## 通过规则

- 所有适用项全部 `pass`，且没有 `unmapped_risks`：状态为 `ready`，可以把剩余的人工判断送入用户验收台。
- 任一适用项 `fail` 或 `blocked`：状态为 `blocked`，先返修，不通知用户验收。
- 任一适用项缺证据或 `unknown`：状态为 `unknown`，先补证据，不通知用户验收。
- 用户退回：保留原证据，重新打开工程项，回到预验收，不得直接改成通过。
- 截图是人工复核附件，不是机器自检替代品，也不自动把工程项改成 `verified`。

## 成本纪律

预验收要复用已有机器门禁、浏览器产物和缓存，不重复喂完整历史上下文；但不能因为 token 或时间成本而跳过真实入口、用户可理解性、失败路径、回滚证据或 PRD 对齐。成本优化只能减少重复读取和无关材料，不能降低交付质量和体验。

## 内置前端共性规范来源

自动挡只抽取知识图谱项目中可跨产品复用的原则：真实浏览器验证、真实结果截图、入口闭环、错误可见、刷新后状态稳定、桌面/窄屏不重叠、读者面降噪、用户结果优先、`unknown` 诚实显示。知识图谱的业务对象、视觉品牌和领域规则不自动复制到其他项目；具体项目规范仍由该项目自己的 `AGENTS.md`、全局规则和产品契约决定。
